# Заявка на бронирование: обновление

Подготовлено 9 ноября 2026. Действующий сайт и VPS из этой среды не обновлялись.

## Что изменено

- Возвращён тёмный каталог, три карточки в ряд на широком экране. Цены занимают одинаковое место; зачёркнутых сумм нет. Выкуп Haval — от 3 500 ₽/сутки.
- Бронирование происходит в форме сайта, без открытия Telegram у клиента. Передаются имя, телефон и выбранный вариант автомобиля. Telegram используется только сервером для доставки менеджеру.
- Доступны варианты МКПП/АКПП, годы Solaris и аренда/выкуп Haval. Заявка не означает подтверждённую бронь.
- Детали раскрываются в карточке. Изображения салонов, Bluetooth и конкретные подогревы не добавлены: фотографий и подтверждённых комплектаций пока нет. Значки известных опций имеют видимые подписи и раскрываемое объяснение.
- Отдельный непредустановленный флажок согласия, отдельные страницы политики и согласия. Сервер проверяет версию согласия, сохраняет её и модель в технической базе.
- Яндекс.Метрика и Google Analytics включаются только после отдельного разрешения; Webvisor отключён. Изменить выбор можно внизу сайта. Заявка работает без аналитики.

## Что нужно до публикации документов

`privacy.html` и `consent.html` сейчас **проекты**. Заполнить оператора (ИП/ООО/ФИО), ИНН, адрес, контакт по данным, срок хранения заявок/переписки; подтвердить получателей, страны, основания обработки и трансграничной передачи. Удалить плашку «Проект документа» только после завершения. Не выдавать шаблон за юридически проверенную политику. VPS в Австрии и Telegram — фактические получатели/маршрут; согласие само по себе не решает требования локализации и трансграничной передачи.

## Порядок технического обновления

**Сначала VPS, затем новый send-booking.php, затем интерфейс.** Старый relay не умеет передавать выбранный автомобиль. Нельзя обновить только index.html и ожидать полной работы бронирования.

1. На существующем VPS просмотреть `relay/update-booking.sh`, затем выполнить его. Скрипт скачивает только app.py и тесты из этой ветки, проверяет SHA-256, делает копию кода в /root, собирает и проверяет relay, сохраняет согласованную SQLite-копию в закрытом Docker-томе и перезапускает только relay. Конфигурация nginx, боты, сертификаты и .env не меняются. При любой ошибке остановиться и изучить вывод. Автоматического отката нет; копии предназначены для ручного восстановления.
2. На SpaceWeb сохранить копии текущих `send.php` и `index.html` **за пределами public_html**.
3. Добавить **send-booking.php** в public_html. Это отдельный relay-only обработчик для обновлённой формы. Текущий send.php оставить: он обслуживает старую страницу и закэшированные версии. Приватный `.yotaxi.env` за пределами public_html оставить на месте. Проверка GET /send-booking.php должна вернуть JSON с предложением использовать форму и HTTP 405.
4. Разместить `index.html`, `site.css`, `callback.js`, `mobile.js`, `privacy.js`, завершённые `privacy.html` и `consent.html` в public_html. Изображения остаются существующими. Не копировать папку relay и весь ZIP репозитория в публичный каталог.
5. Обновить страницу Ctrl+F5. Отправить одну тестовую заявку: выбрать Haval → Выкуп, указать тестовое имя и свой телефон, отметить согласие. В рабочем Telegram-чате должны быть Haval Jolion 2025 — выкуп, имя и телефон. Проверить также обычный заказ звонка. Не использовать реальные чужие контакты для тестов.
6. После проверки удалить больше не нужные резервные копии с контактами по принятой процедуре. Снимок базы содержит персональные данные, не публиковать его и не отправлять в чат.

Миграция добавляет колонки `vehicle` и `consent_version` к существующей таблице без удаления записей. Возвращать старый app.py без восстановления совместимой базы нельзя: старый код использует INSERT без списка колонок. При ручном откате остановить relay и восстановить согласованную пару кода и базы; учесть заявки, пришедшие после резервной копии.

## Проверка разработки

- `python3 -m unittest discover -s relay/tests -v` — relay, миграция, повторные заявки, маршруты nginx.
- `python3 -m unittest discover -s tests -p 'test_*.py' -v` — PHP с локальными заглушками; требуется PHP без cURL (`-n`), переменная PHP_BIN при необходимости.
- Повторить PHP-проверки с `RELAY_PHP_SOURCE=relay/send-via-vps.php`.
- `node tests/callback.test.js`.
- `SITE_URL=http://127.0.0.1:8090/ node tests/booking.browser.cjs` — нужен Playwright и Chromium. Публичные файлы проверяются на отдельном локальном сервере; все отправки и аналитика перехвачены. Реальные сообщения не отправляются.

## Мобильное обновление

Для текущей проверки на SpaceWeb заменить только `booking-preview.html` и папку `booking-preview/` целиком (включая новый mobile.js). Главная страница и её старые JS/CSS остаются на месте. Открыть `/booking-preview.html` на телефоне с обновлением страницы. Обработчик send-booking.php и VPS повторно обновлять не требуется: серверный протокол не изменился.

Добавлены фильтры по коробке, выбор тарифа в карточке, нижняя панель звонка/заявки, сводка выбранной машины с ценой, отдельное состояние успешной отправки и возврат формы в исходное состояние при новом открытии. На телефонах скрыты плавающий чат и второстепенные ссылки первого экрана (доступны в меню); анимация появления больших блоков отключена. Учтены safe-area и prefers-reduced-motion.

`python3 scripts/build-preview.py` синхронизирует отдельный просмотр с основными файлами. `node tests/mobile.browser.cjs` проверяет этот просмотр с перехваченными отправками на ширинах 320/360/375/390/430 px и уменьшенной высоте формы. Это браузерная эмуляция, не проверка на физических iPhone/Android.
