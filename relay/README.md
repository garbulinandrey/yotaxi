# Подписанные заявки с сайта через VPS

PHP send.php на SpaceWeb подписывает JSON с именем, телефоном и случайным
request_id. Заголовки X-Yotaxi-Timestamp и X-Yotaxi-Signature содержат Unix-время
и HMAC-SHA256 от `timestamp + "\n" + raw_body`. Общий RELAY_SECRET — строка из
64 случайных шестнадцатеричных символов. Получатель допускает расхождение часов
до пяти минут. Секрет создаётся на VPS, передаётся на SpaceWeb через закрытый
редактор и не включается в Git, установщик, HTML или журналы.

На SpaceWeb в приватном .yotaxi.env используются RELAY_URL (HTTPS-адрес)
и RELAY_SECRET. При заполненном RELAY_URL обращения к Telegram с хостинга
отключены. RELAY_URL не должен содержать логин, пароль, query или fragment.
PHP-обработчик проверяет имя/номер, ограничивает попытки и ожидает подтверждения
доставки. Он совместим по использованному синтаксису с PHP 7.1, но для сайта
следует отдельно запланировать обновление до поддерживаемой версии PHP.

На VPS Python 3.12, только стандартная библиотека. Служба не использует polling
и не меняет webhook существующего бота. Назначение Telegram фиксируется через
BOT_TOKEN и MANAGER_CHAT_ID, унаследованные от /opt/yotaxi-catalog/.env;
переданные клиентом получатели не используются. Второй env-файл .env содержит
только RELAY_SECRET. SQLite в отдельном Docker volume хранит заявку до отправки.
Записи удаляются спустя семь дней при следующих обращениях. Доступ к БД —
пользователь контейнера/root; обычные HTTP/application logs не содержат контактов.

Успех — только Telegram ok:true или подтверждённый дубль уже отправленной
заявки. Повтор request_id с другим телом отвергается. Одинаковые имя/номер
объединяются в течение десяти минут. При timeout/неясном ответе запись остаётся
unknown/pending и автоматической повторной отправки нет: Telegram не имеет ключа
идемпотентности, и сообщение уже могло уйти. Это предотвращает автоматические
дубли, но НЕ гарантирует доставку при аварии. Неуспешные записи должен разбирать
администратор; сайт предлагает посетителю телефон. Встроенной фоновой очереди
и уведомлений о зависших заявках в этой версии нет.

Общий предел — 30 новых валидных подписанных заявок в минуту; одновременных
обработок восемь. Публично доступен только nginx с HTTPS; порт 8031 привязан
к 127.0.0.1. Нужен сертификат на выбранный домен, проверяемый SpaceWeb, ограничение
размера тела nginx до 4k и rate limit для выбранного маршрута. Не переписывать
существующие server blocks без осмотра и резервной копии. Проверить nginx -t
перед reload. Никогда не отключать проверку TLS и не открывать порт 8031 наружу.

GET /health проверяет только работающий HTTP-процесс, а не доступ к Telegram.
POST /v1/leads — единственный маршрут приёма; без правильной подписи 403.
Настройка nginx/TLS и end-to-end доставка выполнены на VPS; подтверждённое
состояние и проверки приведены ниже. localhost HTTP используется
только для внутреннего соединения nginx-контейнер; SpaceWeb всегда обращается
по HTTPS. Австрийский VPS устраняет прямой путь SpaceWeb -> Telegram, но не
гарантирует отсутствие ограничений на путь SpaceWeb -> VPS.

Проверки без настоящего Telegram: python -m unittest discover -s tests -v.

## Подтверждённая установка — 9 ноября 2026

Пользователь выполнил установку на VPS 82.148.251.22 (Ubuntu); агент не имел
прямого SSH-доступа. Результаты подтверждены выводом команд и получением
реальных тестовых заявок в Telegram.

- Каталог @centrbot2_bot: /opt/yotaxi-catalog, Compose service catalog.
- Справочник @CentrYotaxi_bot: /opt/yotaxi-service, service helper.
- Приёмник: /opt/yotaxi-relay, service relay; 127.0.0.1:8031, volume leads.
- HTTPS: https://vpn.mikhailnet.ru:2053/yotaxi/v1/leads. Nginx проксирует
  подписанные POST-запросы на /v1/leads; POST без подписи даёт JSON error/403.
- Xray использует порт 443 и не перенастраивался. Nginx использует 80/2053.
- Конфигурация vhost: /etc/nginx/sites-enabled/vpn.mikhailnet.ru; резервные
  копии находятся в /root/yotaxi-relay-backups. Лимиты в
  /etc/nginx/conf.d/yotaxi-relay-limits.conf.

SpaceWeb: публичный public_html/send.php заменён relay-only обработчиком,
собранным из двух частей send-vps-part-1.txt и send-vps-part-2.txt. Проверены
успешная подпись и доставка через VPS. Приватные настройки находятся в
родительской папке public_html: имя файла строго .yotaxi.env, с начальной точкой.
Отсутствие точки вызвало 503 после уборки; исправление имени восстановило
отправку. Поля: RELAY_URL и RELAY_SECRET. RELAY_IPV4=82.148.251.22 временно
использовался для обхода сбоя DNS, затем закомментирован и проверена успешная
доставка без IP-привязки. Секрет хранится также в /opt/yotaxi-relay/.env на VPS;
значение не включено в репозиторий. .env контейнеров VPS не удалять.

DNS mikhailnet.ru переключён с истёкшего REG-хостинга на бесплатные ns1.reg.ru
и ns2.reg.ru. Добавлена A-запись vpn -> 82.148.251.22; новые NS и IPv4
подтверждены на VPS после распространения. Пользователь сообщил, что других
сервисов/почты на домене нет.

Сертификат /etc/letsencrypt/live/vpn.mikhailnet.ru/fullchain.pem действителен
до 23 декабря 2026 года. Certbot timer enabled. Authenticator webroot, путь
/var/www/html. Тест certbot renew --cert-name vpn.mikhailnet.ru --dry-run
--non-interactive завершился all simulated renewals succeeded. Действующий
сертификат этим тестом не заменялся. Создан deploy-hook
/etc/letsencrypt/renewal-hooks/deploy/60-yotaxi-nginx-reload: для этого
RENEWED_LINEAGE выполняет nginx -t и systemctl reload nginx. Его ручная проверка
с RENEWED_LINEAGE прошла; Xray не перезапускается. Исходник hook хранится рядом
как 60-yotaxi-nginx-reload.

В SpaceWeb диагностические check-send.php/check-vps.php удалялись при уборке.
Последний временный public_html/check-settings.php следует удалить, если он
ещё остался. Старый public_html/.env перенесён вне public_html в резервную
копию; .yotaxi.env оставлять на месте. Резервные PHP-файлы также вне public_html.
